# 8.3 系统调用错误处理

## 💡 一句话总结

> **系统接口可能失败，程序必须按接口约定检查返回值并处理具体错误。**

---

## 📝 简短解释

许多 Unix 接口失败时返回 -1 并设置 errno，但不是所有函数都遵循同一模式。例如部分线程接口直接返回错误码。

errno 只有在返回值表明失败且接口说明会设置它时才有意义，不能单凭它非零判断刚才的调用失败。后续函数也可能改变它，需要时先保存。

教材把常见检查封装成大写函数，以便突出示例主线；这些包装通常在失败时报告并退出，实际应用可能需要重试、降级或清理后返回。

错误处理也是控制流的一部分，应包含已打开文件、已分配内存等资源的清理。

## 🔎 例子或图解

```text
调用接口 → 检查返回值
            ├─ 成功 → 使用结果
            └─ 失败 → 按约定取得原因 → 清理/重试/返回错误
```

## 🎯 关键要点

- 先看返回值，再按接口约定看错误信息。
- 不要把教材包装函数误认为系统自带函数。
