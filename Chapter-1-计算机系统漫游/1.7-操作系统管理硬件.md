# 1.7 操作系统管理硬件

## 💡 一句话总结

> **操作系统管理和保护硬件资源，并通过进程、虚拟内存和文件等抽象，让应用程序更方便地使用计算机。**

---

## 📝 简短解释

操作系统像管理员：协调资源分配，限制程序互相破坏，并提供统一的服务接口。应用通过系统调用请求文件读写等服务；普通算术指令并不需要每次都调用操作系统。

### 1.7.1 进程

**进程是对一个正在运行的程序的抽象。** 磁盘上的程序文件像菜谱，进程像照菜谱做菜的一次活动。同一个程序可以有多个运行实例。

操作系统会保存和恢复执行状态，让多个进程轮流使用处理器，这叫“上下文切换”。

```text
进程 A 运行
    ↓ 保存 A 的执行状态，恢复 B 的状态
进程 B 运行
    ↓ 保存 B 的执行状态，恢复 A 的状态
进程 A 从先前的位置继续
```

这里的状态包括程序计数器、寄存器等。切换不意味着把进程的全部内存每次都复制一遍。

### 1.7.2 线程

**线程是进程中的执行单元。** 一个进程可以有多个线程，各自执行任务。

```text
一个进程（共享代码、全局数据等资源）
    ├─ 线程 A：处理用户输入
    └─ 线程 B：进行后台计算
```

线程有各自的寄存器状态和栈，但共享进程的地址空间。共享数据方便合作，也意味着同时修改数据时需要协调。多个线程不保证一定更快。

### 1.7.3 虚拟内存

**虚拟内存为每个进程提供自己的地址空间视图。** 程序使用的虚拟地址，需要通过硬件和操作系统维护的映射对应到实际存储位置。

```text
进程 A 的某个虚拟地址 → 物理内存位置甲
进程 B 的相同虚拟地址 → 物理内存位置乙
```

因此，相同的地址数值在不同进程中不一定表示同一块物理内存。

| 区域 | 入门理解 |
|------|----------|
| 代码和数据区 | 保存程序指令、全局数据等 |
| 堆 | 用于运行时动态分配，如 malloc |
| 共享库映射区 | 映射库的代码和数据 |
| 栈 | 支持函数调用，保存返回信息及部分局部数据等 |
| 内核区域 | 教材模型中为内核保留，普通应用不能随意访问 |

虚拟内存不只是“拿磁盘充当内存”，还涉及地址映射、隔离保护和共享。实际地址布局不必与书中的示意图完全一样。

### 1.7.4 文件

在书中的 Unix 模型里，文件提供了字节序列的视图。磁盘文件、终端、网络连接等可以通过统一的 I/O 接口来访问，程序员不用分别掌握每种设备的电路细节。

“像文件一样访问”不表示所有设备都能像磁盘文件一样任意跳转读写位置。

## 🎯 关键要点

| 概念 | 解决的问题 |
|------|------------|
| 进程 | 管理运行中的程序及其资源 |
| 线程 | 在一个进程中组织多个执行流 |
| 虚拟内存 | 提供进程自己的地址空间和保护 |
| 文件 | 为 I/O 提供统一的访问方式 |
