# 1.4 处理器读并解释储存在内存中的指令

## 💡 一句话总结

> **运行程序时，系统把需要的代码和数据装入内存，CPU 执行机器指令，并与输入输出设备配合完成任务。**

---

## 📝 简短解释

### 1.4.1 系统的硬件组成

先把电脑想成一个工作间：CPU 负责干活，内存是工作台，磁盘是长期保存物品的柜子。

| 部件 | 作用 | 类比 |
|------|------|------|
| 总线 | 在部件之间传递信息 | 搬运物品的通道 |
| I/O 设备 | 输入、输出和长期存储，如键盘、显示器、磁盘 | 工作间的对外窗口和储物柜 |
| 主存（内存） | 保存正在使用的指令和数据 | 工作台 |
| CPU（处理器） | 执行机器指令 | 干活的人 |

CPU 内部还要认识三个名词：

- **寄存器**：容量很小、访问很快的存储位置，用来保存运算中正在使用的值。
- **ALU（算术/逻辑单元）**：完成加法、比较等运算的部件。
- **PC（程序计数器）**：保存指令地址的寄存器，帮助 CPU 确定从哪里取指令。

```text
按 PC 指示的地址取指令
          ↓
理解指令要求的操作
          ↓
执行：加载 / 存储 / 运算 / 跳转
          ↓
更新 PC，继续取指令
```

这是入门时的执行模型。实际处理器内部会用更复杂的方式提高速度。“下一条”也不一定紧挨当前指令，跳转可以改变执行位置。

### 1.4.2 运行 hello 程序

在书中的 Linux 环境输入 `./hello` 后，大致会经历：

```text
键盘输入 ./hello
        ↓
shell（命令解释器）识别命令
        ↓
在操作系统帮助下加载程序的代码和数据
        ↓
CPU 执行程序指令
        ↓
经输出服务把 hello, world 显示出来
        ↓
程序结束，shell 等待下一条命令
```

磁盘与内存之间传输数据时，可以使用 **DMA（直接存储器存取）**：CPU 发起或配置操作后，由设备等硬件完成数据搬运，不必由 CPU 逐字节搬运。

## 🎯 关键要点

| 概念 | 记住这一点 |
|------|------------|
| 磁盘与内存 | 一个用于长期保存，一个用于运行时使用 |
| shell | 接收和执行命令的程序 |
| CPU | 执行机器指令，不直接理解 C 源码 |
| 程序运行 | 硬件与操作系统共同配合的过程 |
