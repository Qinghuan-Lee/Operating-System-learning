# 5.11 一些限制因素

## 💡 一句话总结

> **寄存器数量有限和分支预测错误，都可能抵消继续优化的收益。**

---

## 📝 简短解释

**寄存器溢出。** 需要同时保留的值超过寄存器容量时，编译器会把部分值放到栈等内存位置，这叫 spilling，不是整数溢出。过度展开或过多累积变量可能因此变慢。

**分支预测。** 预测正确时能保持执行流畅，预测错误时要撤销错误路径并重新开始，造成开销。随机性强的条件往往更难预测。

条件传送有时能替换分支，但它也可能执行额外工作或增加依赖。不能一概认为“没有 if 就快”。

## 🔎 例子或图解

```text
展开过少 → 控制开销较大
展开适度 → 并行度提高
展开过多 → 活跃值太多 → 溢出到栈 → 额外访存
```

## 🎯 关键要点

- 寄存器溢出与数值溢出是不同概念。
- 分支能否预测常比源码中有几个 if 更重要。
